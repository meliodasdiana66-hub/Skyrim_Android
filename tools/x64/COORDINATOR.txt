Run 4 on the same SHA-256 executed all 212 candidates, 848/848 match, zero divergence. functionsSelected was 212 while the JSON sample stayed at 32 or 64. push/pop added no new leaves. unsupported was 96813, and 83790 of those were sub rsp, imm.

This revision:
  candidatesFound is independent of functionsSelected.
  --max-functions 0 selects every candidate up to 4096, which includes those 212.
  push/pop r64, push imm, and mov through [rsp+disp] are lifted and differential-tested.
  The scanner still rejects calls, jumps, lock, .bind, the entry point, push/pop rsp, and stack slots this leaf did not allocate.
  pe32plus_load.py inventories imports and can map only a synthetic image up to 1 MiB. SkyrimSE is refused for mapping. Imports are not bound. The entry point is not called.
  One push/pop snippet was executed under qemu-aarch64-static on the development VM. That is QEMU user-mode, not a phone, not Adreno, and not the game binary.
  The standalone package skips the 2011 regression instead of failing or calling it a pass. The full repository still runs that regression.

Run 5: 214/214 leaves, 856/856 match. Logical map: 20 intervals, full SizeOfImage 59179008, nothing executed. The common reject `mov [rsp], imm` was opcode C7, which the allowlist did not contain; 32-bit `mov [rsp], reg` was rejected as the wrong width. Both are now accepted only inside a proven frame. `movaps` requires a 16-byte-aligned address. Unicorn on this build does not trap an unaligned MOVAPS, so the scanner rejects that address instead of comparing it. A pointer is stored through only if this leaf computed it from the frame. An incoming register is not a sandbox. A synthetic caller/callee sum matches Unicorn; the leaf scanner still rejects `call`. See ROADMAP.md.

Run 6, same SHA-256, on the owner's PC: 215/215 leaves, 860/860 match, one more leaf than run 5. No XMM leaf was selected. After framed stores, the remaining rejects are dominated by call 41764, jcc 19011, segment 9371, unsupported 25495, and memory_form 12258. Forms still outside the leaf allowlist include test reg, imm 4001 (now lifted, so the next leaf scan can accept a straight-line test), call mem[reg] 3459, call mem[rip] 2289, and reg, imm 1605, and cmp mem[rip], imm 2221.

Windows CRT text mode stopped the binary Cpu64 fread at byte 0x1A. The harness now calls _setmode(_O_BINARY) on stdin and stdout before any fread or fwrite when compiled for _WIN32. Delete the temporary clang.exe wrapper that force-included _setmode. The package does not depend on that wrapper. Linux cannot reproduce the CRT bug; the regression checks that _setmode appears before fread and that a 0x1A/CRLF payload round-trips.

cfg_sandbox.py is a separate bounded guest, not a change to the leaf scanner. It compares one explicit direct call plus a forward jz, and a jb after sub, with Unicorn, including CF/OF/SF/ZF/PF. The instruction addresses Unicorn actually executed are reported. Loops, recursion, indirect calls, unknown targets, stack escapes, and non-executable targets are rejected. A missing import is a named unbound_import failure. discover_closed is read-only: a .pdata entry is not eligibility, .bind is not code, and a closed graph is not executed. and reg, imm was not added. QEMU user-mode ran the lifted test-immediate flags. That is not a phone and not Adreno.

Still unsupported for a playable port: indirect calls, backward branches, untracked memory, indexed LEA, LOCK, RSP push/pop, segment overrides, D3D11/DXGI binding, TLS callbacks, exception dispatch, audio, BSA/ESM, and any ARM64 Android run of the game.
